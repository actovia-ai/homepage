Actovia uses two bundled open-source engines:
[agent-desktop](https://github.com/vercel-labs/agent-desktop) for desktop apps
and [agent-browser](https://github.com/vercel-labs/agent-browser) for websites.
The selected model reads the available controls, takes an action, then checks
the result. You can use these tools in Chat and Philharmonic.

<Callout type="warn" title="Experimental">
  Automation can act on the wrong control or misunderstand a result. Follow its
  tool activity and stop the current run if needed. **⌥⇧⎋** (Option-Shift-Escape
  on macOS; Alt-Shift-Escape on Windows/Linux) interrupts active desktop and
  browser actions on the host.
</Callout>

Configure both engines in the **Mac app → Settings → Computer & Browser Use**.
These host settings are not exposed in a paired browser terminal.

## Desktop automation

Computer Use is **off by default**. To enable it:

1. Open the apps you want the AI to work in.
2. Turn on **Enable Computer Use**.
3. Add those apps under **Allowlisted apps**. The picker lists running apps,
   not every installed app. An app must still be running when the AI uses it.
4. Set **Max steps** if needed. The default is **25** observations and actions
   per agent run; the allowed range is 1–100.

Only allowlisted targets are accepted, and Actovia cannot target itself.
The engine reads the app's accessibility tree and acts on the controls it
finds. Actovia uses its headless mode: actions do not move your pointer or
take focus. This replaces the earlier screenshot-and-mouse loop; there is no
**Settle delay** setting in the current UI.

For example, ask: “In Notes, create a note called Weekend checklist and add
these three items…” The model observes the running app first, then uses
references from that observation and observes again to verify the result.
If an app exposes too little accessibility information, the task may be
blocked even when its window is visible.

### macOS permissions

Desktop accessibility actions require **Accessibility** permission. Open
**System Settings → Privacy & Security → Accessibility**; on newer macOS
versions the page may be called **Device Control and Data Access**. Grant
access to the Actovia host or helper identified by the permission request,
then retry the task. Development builds can be identified differently from
the installed app, so follow the actual process named by macOS.

Screen Recording is needed for screenshot operations in the upstream engine;
it is not a prerequisite for Actovia's current accessibility-only desktop
workflow. The old instruction to enable both permissions before every task
no longer applies. See the engine's
[permission guide](https://github.com/vercel-labs/agent-desktop/blob/v1.1.0/docs/install.md#permissions)
if a permission error remains.

## Browser automation

Browser Use operates a **separate browser session on the host computer**.
It does not attach to your normal browser, inherit its tabs or reuse its
signed-in cookies. Desktop app allowlists do not apply to this session.

| Setting                 | Default | What it changes                                                                                     |
| ----------------------- | ------- | --------------------------------------------------------------------------------------------------- |
| Enable Browser Use      | On      | Allows browser actions. Turning it off blocks the next action; an existing session can still close. |
| Show browser window     | Off     | Shows the automated browser so you can follow it. Changes apply to new sessions.                    |
| Browser actions per run | 100     | Limits browser calls in one agent run (1–500). Closing remains possible after the limit.            |

Ask for a concrete website task, such as “Open the project documentation and
find the installation requirements.” The model navigates, inspects the page,
acts on its controls and checks the outcome. It should ask you when a login,
CAPTCHA or an owner-only decision is required. Each agent run gets its own
session, which is closed when the run ends.

Actovia uses an installed Chrome, Edge or Chromium when it finds one. If
browser startup reports a missing executable, install a supported browser
on the host and retry. Showing the automated browser window does not switch
it to your personal browser profile.

## Follow or stop a run

Tool activity in the conversation shows the automation engine, command and
result, including failures. The current engine reports structured controls
and action results, rather than the old per-step screenshot card.

Use the conversation's **Stop** control to cancel a run, or the host's
**⌥⇧⎋** shortcut to interrupt active automation calls. If a step budget is
reached, the model should report what remains instead of silently continuing
through another route. Allowlist and enable switches are checked again on
subsequent actions.

## Three browser features, three purposes

- **Browser Use** lets the AI interact with websites in its own host session.
- **[Web search & fetch](/docs/tools/web)** retrieves search results and page
  content without operating a browser UI.
- **[Actovia Web](/docs/web)** lets you use Chat and Philharmonic from a paired
  remote browser. It is a device connection, not an automation engine.
